Ажлын зорилго ба товч агуулга: Энэхүү бие даалтын ажил нь орчин үеийн их хэмжээний өгөгдөл боловсруулах шаардлагад нийцүүлэн үүссэн NoSQL өгөгдлийн сангуудын онолын үндэс, дөрвөн үндсэн төрлийн архитектурын ялгаа, CAP теоремийн практик ач холбогдол болон өгөгдөл загварчлалын зарчмыг системтэйгээр судлахад чиглэнэ. Онолын судалгаанд тулгуурлан MongoDB платформ болон Python (PyMongo) орчинд цахим худалдааны бүтээгдэхүүний каталогийн туршилтын системийг загварчлан байгуулж, CRUD үйлдлүүд, индексжүүлэлт, текст хайлт болон Aggregation Pipeline-ийн дэвшилтэт боломжуудыг туршин, хамааралт (SQL) системтэй харьцуулсан дүн шинжилгээ хийв.

1. Онолын судалгааны хэсэг

1.1. SQL ба NoSQL — Суурь ойлголт

Өгөгдлийн сангийн удирдлагын системүүд (DBMS) нь програм хангамжийн инженерчлэлийн суурь дэд бүтэц болж ирсэн. 1970 онд Эдгар Коддын боловсруулсан хамааралт загвар (Codd, 1970) нь өгөгдлийг мөр, баганаас бүрдэх хүснэгт хэлбэрээр зохион байгуулж, хүснэгт хоорондын холбоосыг гадаад түлхүүр (Foreign Key)-ээр илэрхийлэх замаар өгөгдлийн давхардлыг бууруулж, бүрэн бүтэн байдлыг баталгаажуулсан юм. Энэхүү зарчим дээр суурилсан RDBMS (Relational Database Management System — жишээ нь PostgreSQL, MySQL, Oracle, MS SQL Server) нь SQL (Structured Query Language) хэл ашиглан хатуу тодорхойлсон схем (Schema-on-Write) болон ACID (Atomicity, Consistency, Isolation, Durability) гүйлгээний баталгааг хангадаг.

Гэвч 2000-аад оны дунд үеэс интернэт хэрэглэгчдийн тоо огцом өсөж, нийгмийн сүлжээ, цахим худалдаа, үүлэн тооцоолол болон IoT төхөөрөмжүүдээс секунд тутамд асар их хэмжээний бүтэцгүй болон хагас бүтэцтэй өгөгдөл (Big Data) үүсэх болсон. Уламжлалт RDBMS архитектур нь дараах гурван үндсэн сорилттой тулгарсан (Sadalage & Fowler, 2012):

  • Хэвтээ өргөтгөлийн хязгаарлалт (Horizontal Scaling): Хамааралт өгөгдлийн сан нь хүснэгт хоорондын JOIN үйлдэл болон ACID гүйлгээг хадгалахын тулд ихэвчлэн нэг хүчирхэг серверийн хүчин чадлыг нэмэгдүүлэх буюу босоо өргөтгөлт (Vertical Scaling / Scale-up) хийдэг. Харин NoSQL нь олон энгийн серверийн кластерт өгөгдлийг тараан байрлуулах (Scale-out) зарчмаар бүтээгдсэн.
  • Схемийн уян хатан бус байдал: Бизнесийн шаардлага хурдан өөрчлөгддөг орчин үеийн веб системүүдэд өгөгдлийн бүтэц байнга шинэчлэгддэг. Сая сая бичлэгтэй SQL хүснэгтэд ALTER TABLE хийх нь системийг удаашруулах эсвэл зогсолт (downtime) үүсгэх эрсдэлтэй.
  • Их хэмжээний өгөгдөл ба тархсан системийн хэрэгцээ: Өндөр ачаалалтай системүүдэд секундийн мянганы нарийвчлалтай хариу үйлдэл (low latency), тасралтгүй ажиллагаа (high availability), газарзүйн олон бүсэд өгөгдөл хуулах (geo-replication) чадвар шаардагддаг. NoSQL нь ACID-ийн хатуу шаардлагыг тодорхой хэмжээнд сулруулж, BASE загварыг нэвтрүүлснээр тархсан орчинд өндөр гүйцэтгэл гаргах боломжийг олгодог (Kleppmann, 2017).

1.2. NoSQL системүүдийн 4 үндсэн төрөл

1) Key-Value Store (Redis, DynamoDB): Хамгийн энгийн бүтэцтэй, O(1) хурдтай. Сесс, сагс, вэб кэшлэлтэд тохиромжтой.
2) Document Store (MongoDB, CouchDB): JSON/BSON баримтуудаар хадгалдаг. Шаталсан талбар, массив дээр индекс үүсгэдэг.
3) Column-Family Store (Cassandra, HBase): Bigtable загвартай, өндөр хурдны бичилт, цагийн цуваа өгөгдөлд тохиромжтой.
4) Graph Database (Neo4j): Орой ба ирмэгээр хадгалдаг, index-free adjacency хөдөлгүүртэй тул сүлжээний хайлтад онцгой.

1.3. CAP Теорем ба 1.4. Загварчлал

Тархсан системд Consistency (C), Availability (A), Partition Tolerance (P) гурваас нэгэн зэрэг хамгийн ихдээ хоёрыг л хангана. Сүлжээний тасралт (P) гарцаагүй тул бодит системүүд CP (MongoDB) эсвэл AP (Cassandra) загварыг сонгодог. Netflix нь 200 сая хэрэглэгчийн үзэлтийн түүхийг Cassandra-ийн AP зарчмаар 99.999% найдвартай ажиллуулдаг.

3. Дүн шинжилгээ ба Харьцуулалт

3.1. SQL-тэй харьцуулсан давуу тал: Олон төрлийн барааны техникийн үзүүлэлтийг specs дэд объектод хялбархан хадгалж, JOIN үйлдэлгүйгээр ганцхан find_one() асуулгаар сэтгэгдэлтэй нь хамт хурдан уншсан.
3.2. Ажиглагдсан сул тал: SQL шиг гадаад түлхүүрийн хатуу хяналт анхдагчаар байхгүй, өгөгдлийн давхардал үүсэх, талбарын нэр давтагддаг тул санах ой илүү зарцуулдаг.
3.3. Өөр хэрэгцээний NoSQL төрлүүд: Сагс болон сессэд Redis, зөвлөмжийн системд Neo4j, их хэмжээний логт Cassandra тохиромжтой.
3.4. Хамгийн чухал ойлголт: Төгс өгөгдлийн сан гэж байдаггүй; өгөгдлийн загварчлал болон CAP-ийн сонголт нь бизнесийн уншилт-бичилтийн шаардлагаас шууд хамаардаг.

4. Дүгнэлт ба Санал зөвлөмж

Энэхүү бие даалтын ажлаар NoSQL өгөгдлийн сангуудын онол, архитектур, CAP теорем, өгөгдөл загварчлалын зарчмыг цогцоор судалж, MongoDB платформ дээр 25 барааны өгөгдөлтэй цахим худалдааны системийг амжилттай хэрэгжүүлэн баталгаажууллаа.
